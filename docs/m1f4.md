## 行为

- 分析成功、打开示例、历史重开后，先完成本地历史保存，再写入论文 hash；恢复成功将 URL 规范化且不新增重复历史项。
- 浏览器后退/前进、手工改变 hash 均由 `hashchange` 恢复；应用内导航使用 History API 写 URL，避免自己重复触发恢复。返回首页、换一篇论文、新建分析时清除 hash，保留原 pathname/query。
- 从 `papertutor-history.records` 查找匹配论文；没有历史时，必须同时存在 `papertutor-cache.docs` 与 `analyses` 才恢复完整结果。不会触发上传、解析或分析。
- `ResultView` 继续按论文 hash 读取 `progress`，保留 `activeStep` 和已展开的自测题；原有手动历史重开、删除同步清理进度仍有效。
- 未知/非法 hash、无完整本地缓存、IndexedDB 不可用或读取失败时，首页显示“本地没有这篇论文的缓存，请重新上传”和“回首页”按钮；不弹错误对话框、不自动分析。
- 恢复及浏览器路由切换禁用自动 health 与帮助预取；普通首页及主动打开示例仍保留 M1-F3 行为。按需帮助仍需用户点击；用户回首页或重新上传后才恢复正常服务检查。

## 已知边界

- 只恢复同源、同浏览器保存的完整结果；URL 本身不携带论文内容，也不提供跨设备同步。缓存被清除/淘汰或仅剩解析文档时显示提示，不补发网络请求。
- 历史最多 10 条、进度最多 20 条的原有保留策略不变。删除历史会删除进度，但不会删除独立解析/分析 cache；若完整 cache 仍在，旧 URL 仍可恢复结果（不会恢复已删除的进度）。
- 存储缺失与读取失败共用友好提示，不向用户弹出原始 IndexedDB 错误。打开被阻塞会降级；解除阻塞后可刷新重试。
- 恢复入口延后健康检查，恢复页顶部服务模式不会代表已重新确认的线上状态；用户主动回首页/上传后检查。恢复不会自动发 Function 请求，但静态应用和示例资源仍可加载；不等同于离线首次加载整个站点。
- 只验证本地 mock 和 Edge 模拟桌面/移动视口；未验证真实移动设备、线上部署、真实 DocMind/LLM。未改站点描述、部署形态或访问权限，未操作线上 parse/analyze/help。
